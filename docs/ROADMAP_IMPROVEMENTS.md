# V2Ray Auto 改进路线图

> 状态：P0–P1 决策完结（已实现项标 ✅，产品取消项标 ❌）；P2 未开始
> 日期：2026-08-15
> 范围：基于现状诊断的产品/工程改进方向，按优先级排序

---

## 0. 现状诊断

### 优势（应保持）
- 架构清晰：`core`（纯 Python）→ `api`（Flask）→ `desktop`（Electron）三层分离
- 核心逻辑为纯函数、可测试（现有 407 行测试）
- 部署流程完整：bootstrap → 安装 → 配置 → REALITY 自测 → 防火墙
- 桌面端体验已打磨：凭据加密存储（safeStorage）、日志轮转（按天 / 保留 30 天）、图标 SVG 化、部署历史
- 工程细节扎实：配置 hash 比对避免无谓重启、端口占用回退、启动超时兜底

### 主要短板（按严重度排序）
1. **只装不卸**：一键部署只有"部署"，没有"卸载 / 更新 / 回滚"
2. **多服务器管理弱**：每次部署都需重填服务器信息，无地址簿 / 凭据复用
3. **缺少"使用"闭环**：生成 clientUri 后需手动复制到外部客户端，无本机启动 / 导入能力
4. **健壮性缺口**：无并发部署保护、无部分失败的恢复机制

## 1. P0 基础完善（建议优先）

### 1.1 卸载入口
- **目标**：部署过的节点可一键撤销，与部署对称
- **范围**：在部署历史中，对成功节点提供「卸载」操作
- **实现要点**：
  - 停用 systemd 服务（`xray.service`）
  - 删除远端配置与安装文件（`/usr/local/etc/xray/`、二进制）
  - 关闭已开放的端口（本地防火墙，反向操作 `_open_firewall`）
  - 幂等：卸载已卸载的节点不报错
- **验收**：部署 → 卸载 → 端口/服务/文件均恢复到部署前状态
- **状态**：✅ 已完成（`/api/uninstall` + 前端历史「卸载」入口；停/禁用 systemd 服务、删除远端配置与状态文件、逆序关闭已开放的防火墙端口；幂等可重复、崩溃后可恢复）

### 1.2 服务器地址簿
- **目标**：保存多个服务器（地址 + 凭据引用），部署时可选择或新建
- **范围**：恢复节点管理能力，但定位为「地址簿 + 凭据复用」，而非旧的节点快照
- **实现要点**：
  - 复用现有 `safeStorage` 加密凭据存储，绑定 `ip@username`
  - 列表：名称 / IP / 用户名 / 备注，可增删改
  - 部署表单支持「从地址簿选择」或「手动填写」
  - 注意：此前删除节点功能时已移除 `nodes.*` IPC，需重新设计数据模型（名称/备注字段比旧版更完善）
- **验收**：保存服务器 → 下次部署下拉选择即自动填充
- **状态**：❌ 已取消（产品决策：多节点 / 地址簿能力随桌面端节点功能一并下线——`nodes.*` IPC 已删除；凭据仍由 safeStorage 按 `ip@username` 在单次部署中自动回填，逐台部署即可，无需地址簿管理）

### 1.3 并发 / 幂等保护
- **目标**：同一时间只允许一个部署任务；部署接口幂等
- **实现要点**：
  - 后端加部署锁（进程内锁即可，桌面端单实例）
  - 部署中再次发起 → 拒绝并提示「已有部署进行中」
  - 前端部署按钮在部署期间禁用（已有 `deploying` 状态）
  - 部署接口对已存在的服务走「更新配置」语义而非报错
- **验收**：并发请求只有一个成功，其余明确拒绝
- **状态**：✅ 已完成（后端进程内互斥锁 `_remote_op_lock`，并发部署/卸载请求返回 `LockedOperationError`（409）拒绝；前端部署/卸载按钮运行期禁用）

## 2. P1 体验闭环

### 2.1 本机客户端集成
- **目标**：部署成功后真正"点一下就能用"，不依赖外部客户端
- **范围**：
  - 生成可导入的本地配置 / 订阅链接
  - 可选：桌面端内置 Xray 客户端，一键启动本机代理（系统代理或 socks5）
- **实现要点**：
  - 部署结果新增「导入到本机」「启动代理」操作
  - 本机 Xray 二进制随包分发或引导下载
  - 代理状态展示（运行中 / 已停止 / 端口）
- **验收**：部署 → 一键启动 → 浏览器可访问外网
- **状态**：❌ 已取消（产品决策：不考虑本机客户端集成；用户使用外部客户端导入部署结果）

### 2.2 部署进度增强
- **目标**：终端日志已是流式，补齐「取消」能力
- **实现要点**：
  - 部署中提供「取消」按钮，向后端发送中断信号
  - 后端优雅中断 SSH 会话并清理已创建的临时文件
- **验收**：部署 30 秒后取消，远端不残留半成品状态
- **状态**：✅ 已完成（`POST /api/cancel` + `threading.Event` 协作式取消；SSH run 循环检测信号后中断；前端「取消部署」按钮 + 历史「已取消」标记；取消时按逆序回退已完成的步骤：关防火墙 → 停/禁用服务 → 删配置目录；xray 二进制与 REALITY state 保留以便复用，与卸载语义一致）

### 2.3 节点健康检查
- **目标**：标记已部署节点的可用性
- **实现要点**：
  - 对已部署节点定期做连通性探测（TCP/HTTP）
  - 失效节点在列表中标红 / 提示
- **验收**：停掉远端服务后，客户端在合理时间内标记节点不可用
- **状态**：❌ 已取消（产品决策：节点连不上通常意味着服务器 IP 被封，直接部署新服务器即可，无需健康监控）

## 3. P2 规模化

### 3.1 协议扩展
- **目标**：除 VLESS + REALITY / VMess 外，支持更多协议
- **候选**：Trojan、Shadowsocks、WireGuard（作为可选 profile）

### 3.2 订阅聚合
- **目标**：将多个部署节点聚合成订阅链接，一键导入到客户端
- **实现要点**：地址簿基础上生成聚合 `clientUri` 列表

### 3.3 测试补强
- **目标**：补齐部署健壮性测试
- **范围**：
  - installer 的部分引导失败恢复
  - SSH 执行器 mock 集成测试
  - 并发锁、卸载幂等的单元测试
